# החלטות שקיבלתי לבד (לילה, 2026-11-04)

לפי ההוראה: החלטה שלא כתובה בהנחיות — האפשרות הפשוטה ביותר, עם תיעוד כאן.

## 1. פונקציות פענוח המייל עברו ל-`import_export.py`
`parse_message` (ומה שהיה `parse_date` / `parse_body`) משמשות רק את הייבוא. הן עברו מ-`messages.py`
ל-`import_export.py`, כך שכל קוד מסלול המיילים בקובץ אחד, ו-`messages.py` מכיל רק את פורמט ההודעה.
`parse_date` ו-`parse_body` אוחדו לתוך `parse_message` (פונקציה אחת שקל לקרוא מלמעלה למטה).

## 2. `clean.py` לא קוצר
68 שורות, כל פונקציה עושה דבר אחד, והוא מכיל תווים בלתי נראים (`‎`...) שקל לשבור בעריכה.

## 3. מדידת זמנים — ה-Embedding של השאלה מחושב בנפרד
כדי לפרק את הזמן לשלבים (ניסוח / Embedding / חיפוש / LLM), ה-Embedding של שאלת החיפוש מחושב
ב-`prepare` ומועבר ל-`QueryBundle(embedding=...)`. ה-retriever של LlamaIndex משתמש בו ולא מחשב שוב —
כלומר אין קריאה נוספת, רק פיצול של אותה עבודה לשני מדידים. הזמנים נמדדים רק ב-`ask` (הערכה ו-CLI),
לא בממשק.

## 4. סימון "יש מידע / אין מידע" (בעיה #8) — קריאת LLM אחת לכל מנה של 10 הודעות
- **איך:** באינדוקס, לכל מנה (ממילא יש מנות של 10 בגלל מגבלת ה-API) — קריאה אחת ל-lite שמחזירה JSON
  `[{"id": 1, "has_info": true}, ...]`. לא לפי סימן שאלה (נכשל — "אז המבחן ביום שני?" היא שאלה עם מידע).
- **בכשל:** כל ההודעות במנה מסומנות "יש מידע" — כלומר בלי הורדת ציון (המצב הבטוח: כמו בלי הפיצ'ר).
- **איפה מורידים ציון:** רכיב `NoInfoPenalty` **לפני** הסף — כך הודעה בלי מידע יכולה גם לרדת מתחת לסף.
- **כבוי כברירת מחדל:** `NO_INFO_PENALTY = 1.0` ב-`config.py`, עד שהניסוי יראה שזה משפר.
- `TEXT_VERSION` 2 → 3 (נוסף שדה ל-metadata) → בנייה מחדש.
